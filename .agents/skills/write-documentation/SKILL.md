# Write Documentation

読者に伝わる文書をつくるための方針です。技術文書は「データの羅列」ではなく、読者が読み進めるうちに理解が積み重なる「文書」でなければなりません。

## 文書の基本姿勢

文書は **意図** と **勾配** を持つ。この2つが欠けた文書は、どう整えても読者に届かない。

- **意図**：何のために書くか（読者が読んだあとに何ができる・分かるか）を、文書または節の冒頭で前置きする。コマンドやFieldの説明でも、「何に使うか」を先に述べてから使い方へ進む
- **勾配**：読者が読み進めるうちに理解が積み重なる順に並べる。AIが書く文章は常に一定で文章に勾配が一切ない。人間の書く文章は、伝えたいコンテキストの重要度や順番に応じて必ず勾配がつく。
- **読者の立ち位置**：専門用語を説明なしに出さない。読者が「これは何？」「なぜ？」「どういう意味？」と立ち止まる箇所を残さない
- **意味のある情報だけ残す**：見たところで何も伝わらない文章はない方がマシ。「書いている風」を醸し出さない。無駄な文を追加するのは負債を積み上げるだけであり、何の仕事ももたらしていない。

## 表現

- **用語**：プロジェクト独自の概念名や一般的でない英単語は自然な日本語へ。一般的に英語で書かれることの多い技術用語のみ英語でよい。
- **略語・造語禁止**：GPT臭い略語・造語（例：Fractional Frame、Weighted Energy平方根）を使わない。定着した略語以外は、展開するか自然な日本語へ書き換える
- **自然な日本語**：直訳臭い表現を読み直す。具体例：
  - 「対応するtype」→「イベントの種類」
  - 「Duration外のEvent」→「`--duration-frames`を超えるフレームのイベント」
  - 「未解決Parameter ID」→「音源定義に存在しないパラメータID」
  - 突然出てくる「並べる」「Sort」→「時系列へ処理するため、昇順へ整列する」
- **メタ記述禁止**：直近の文脈、ユーザーの指摘理由、単なる差分、過去の状態、進行管理上の名称（phaseN、MVP、P0 など）を書かない。永続化すべき事実だけを残す

## 排除するもの

ソースコードや他docsの領分は書かない。

| 排除するもの | 理由 | 代替 |
|---|---|---|
| 実装詳細（数式・係数・マジックナンバー） | ソースコードの正本を見れば分かる | 振る舞いで説明する |
| コードの翻訳（typedef、関数羅列、信号Path羅列） | コードそのもの | 設計意図だけを書く |

### GPTの悪癖

GPTモデルは特にドキュメントの品質が悪い。以下にGPT特有の悪癖を書く。これは避ける。

- 段落・章立てをすぐ分ける: なぜかGPTはすぐに段落と章立てを切り替える。そのせいで同じような内容がいろんな個所に散らばる。とにかく読みにくく醜い文書。
- 散文、箇条書きを連打、すぐに改行、一般的に使わない英単語交じりの日本語。 「これはAではない、Bである。（このGPT構文は特に嫌い）」
- 特に理由のない「否定文連打」。なぜかGPTは「～ない」「～しない」といった否定文を連打したがる。基本的に文章は肯定文のみで伝わるはず。否定文でなければならない明確な理由がある場合のみ否定文を使ってよい。
- ドキュメントは差分を残すのではない。ユーザーの指摘や思考内容をそのままドキュメントに反映してはいけない。

## 構造化

- 箇条書きの連打を避ける。同じ属性の並びは表へ、手順は番号付きへ、分岐は見出し分割へ振り分ける
- 同じような内容は1箇所へ集約する。同じ説明を複数箇所で繰り返さない
- 図（Mermaid）や表を、読者の理解を助ける場面で使う。表や図にも「ここから何を読み取るか」を添える。データ羅列を表へ置き換えただけのものは、文脈を前置きして読みやすくする
- 他docsと重複する内容を書かない。内容を移動するときは、移動元・移動先・参照を同時に更新する
- 文書を書く前に、全体の情報構造を設計すること。1つの概念・機能・論点は原則1箇所に集約し、同じ説明や図を別章で繰り返さない。章ごとの切り分け基準を統一し、章タイトルと内容を一致させる。長文では目次を付ける。

## 書く前・書いた後の確認

**書く前**：
- 読者は誰か、読んだあとに何ができるようになるかを決める
- その内容は本書の範囲か。他docsの領分でないかを確認する
- 全体の情報構造を設計する。章ごとの切り分け基準を統一し、章タイトルと内容を一致させる。1つの概念・機能・論点は原則1箇所に集約し、同じ説明や図を別章で繰り返さないようにする。

**書いた後**：
- 読者が立ち止まりそうな用語・表現を読み直す（「これは何？」「なぜ？」「どういう意味？」を自問する）
- 他docsとの重複がないか確認する
- 「書いている風」の文章（意味のない装飾、受け身的な説明、データの羅列だけの節）を削る
- 文書全体を通読して、情報の重複・分断・章の不整合・説明順の逆転がないか確認する。
