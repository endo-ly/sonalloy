# Write Documentation

読者に伝わる文書をつくるための方針です。技術文書は「データの羅列」ではなく、読者が読み進めるうちに理解が積み重なる「文書」でなければなりません。

## 適用条件

| | 内容 |
|---|---|
| 対象 | `docs/*.md`、`SKILL.md`、`README.md` など、読者へ向けて書く文書の作成・編集・整形・レビュー |
| 対象外 | コードコメント、コミットメッセージ、Diagnostic、実装作業そのもの |

## 文書の基本姿勢

文書は **意図** と **勾配** を持つ。この2つが欠けた文書は、どれ整えても読者に届かない。

- **意図**：何のために書くか（読者が読んだあとに何ができる・分かるか）を、文書または節の冒頭で前置きする。コマンドやFieldの説明でも、「何に使うか」を先に述べてから使い方へ進む
- **勾配**：読者が読み進めるうちに理解が積み重なる順に並べる。読者のやりたいことの流れを見出しの軸にする（例：作る → 検証する → 鳴らす → エラー対応）
- **読者の立ち位置**：専門用語を説明なしに出さない。操作には「なぜそうするか」を添える。読者が「これは何？」「なぜ？」「どういう意味？」と立ち止まる箇所を残さない
- **意味のある情報だけ残す**：見たところで何も伝わらない文章はない方がマシ。「書いている風」を醸し出さない

## 構成

- 冒頭に「本書の範囲」を置き、**本書で扱わない内容**を他docsへ明示する（MECE）
- 見出しは読者のプロセス（やりたいことの順）を軸にする。データの分類（コマンド順、Field順、ファイル順）は読者の関心と合わないことが多い
- 他docsと重複する内容を書かない。内容を移動するときは、移動元・移動先・参照を同時に更新する

## 表現

- **用語**：プロジェクト独自の概念名や一般的でない英単語は自然な日本語へ。一般的な技術用語はそのまま
- **略語・造語**：GPT臭い略語・造語（例：Fractional Frame、Weighted Energy平方根）を使わない。定着した略語（STFT、FFT、LFOなど）以外は、展開するか自然な日本語へ書き換える
- **自然な日本語**：直訳臭い表現を読み直す。具体例：
  - 「対応するtype」→「書けるEventの種類」
  - 「Duration外のEvent」→「`--duration-frames`を超えるFrameのEvent」
  - 「未解決Parameter ID」→「音源定義に存在しないParameter ID」
  - 「並べる」「Sort」→「時系列へ処理するため、昇順へ整列する」
- **メタ記述禁止**：直近の文脈、ユーザーの指摘理由、単なる差分、過去の状態、進行管理上の名称（phaseN、MVP、P0 など）を書かない。永続化すべき事実だけを残す

## 排除するもの

ソースコードや他docsの領分は、docsへ書かない。詳細は正本へ委ね、参照を明示する。

| 排除するもの | 理由 | 代替 |
|---|---|---|
| 実装詳細（数式・係数・マジックナンバー） | ソースコードの正本を見れば分かる | 振る舞いで説明する（例：「Feedbackは直前Sampleで位相を変調する」） |
| コードの翻訳（typedef、関数羅列、信号Path羅列） | コードそのもの | 設計意図だけを書く |
| プロジェクト固有のPath（`examples/`、`testdata/`、`scripts/`） | 手順書を汎用に保つため | プレースホルダ（`<definition>`、`<WAVへの相対Path>`）を使う |
| 詳細すぎる文言 | 読者の関心と合わない | 正本へ委ね、参照を明示する |

## 構造化

- 箇条書きの連打を避ける。同じ属性の並びは表へ、手順は番号付きへ、分岐は見出し分割へ振り分ける
- 同じような内容は1箇所へ集約する。同じ説明を複数箇所で繰り返さない
- 図（Mermaid）や表を、読者の理解を助ける場面で使う。表や図にも「ここから何を読み取るか」を添える。データ羅列を表へ置き換えただけのものは、文脈を前置きして読みやすくする

## 書く前・書いた後の確認

**書く前**：
- 読者は誰か、読んだあとに何ができるようになるかを決める
- その内容は本書の範囲か。他docsの領分でないかを確認する

**書いた後**：
- 読者が立ち止まりそうな用語・表現を読み直す（「これは何？」「なぜ？」「どういう意味？」を自問する）
- 他docsとの重複がないか確認する
- 「書いている風」の文章（意味のない装飾、受け身的な説明、データの羅列だけの節）を削る
